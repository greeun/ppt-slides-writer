# AI Slop 체크리스트

AI가 생성한 디자인에서 반복적으로 나타나는 시각적 패턴("AI 냄새")을 식별하는 공유 참조 문서.
gstack(Garry Tan)의 AI Slop Blacklist를 기반으로 Frentis 맥락에 맞게 재구성.

> **이 파일은 단일 진실 소스(SSOT)**. 각 스킬(design-guide-builder, slide-reviewer, frontend-design 등)은
> 자기 도메인에 맞는 항목만 발췌하여 참조한다.

## 블랙리스트 10가지

### 1. 보라/인디고 그라데이션 배경

- **탐지**: `linear-gradient`에 `#6366f1`~`#8b5cf6` 범위(Tailwind indigo-500~violet-500) 포함
- **문제**: AI SaaS 템플릿의 대표 시그니처. 즉시 "AI가 만들었구나" 인상
- **대안**: 브랜드 고유 색상 사용, 그라데이션 대신 단색 배경 또는 미묘한 텍스처

### 2. 3컬럼 피처 그리드

- **탐지**: grid/flex 컨테이너에 정확히 3개 자식, 각각 원형 요소 + 제목 + 설명 구조
- **문제**: 가장 인식 가능한 AI 레이아웃 패턴. 모든 AI 생성 랜딩 페이지의 기본형
- **대안**: 비대칭 레이아웃, Bento 그리드, 단일 피처 딥다이브, 스크롤 인터랙션

### 3. 색깔 원 안의 아이콘

- **탐지**: `border-radius: 50%` 원형 컨테이너 안 장식용 아이콘
- **문제**: SaaS 스타터 템플릿의 시그니처. 아이콘이 정보 전달이 아닌 장식 역할
- **대안**: 아이콘 없이 텍스트만, 또는 아이콘을 인라인으로 자연스럽게 배치

### 4. 모든 것 가운데 정렬

- **탐지**: `text-align: center`가 텍스트 컨테이너의 60% 이상
- **문제**: 시각적 위계 부재. 모든 것이 같은 무게로 보임
- **대안**: 좌측 정렬 기본, 히어로/CTA만 선택적 가운데 정렬

### 5. 균일한 둥근 모서리

- **탐지**: 동일한 `border-radius` 16px 이상이 요소의 80% 이상
- **문제**: 의도적 디자인 계층이 아닌 기계적 균일성
- **대안**: 계층별 차등 radius (sm: 4px, md: 8px, lg: 12px, full: pill 버튼만)

### 6. 장식용 블롭/웨이브 디바이더

- **탐지**: 떠다니는 원, 웨이브 SVG 디바이더, 그라데이션 블롭 배경
- **문제**: 빈 공간을 장식으로 채우는 것은 콘텐츠 부족의 증거
- **대안**: 섹션이 비어보이면 콘텐츠를 보강하거나 여백을 의도적으로 활용

### 7. 이모지를 디자인 요소로 사용

- **탐지**: 제목에 로켓/별/불꽃, 불릿 포인트에 이모지, 섹션 헤더 이모지
- **문제**: 즉시 AI 생성물로 인식됨. 전문성 저하
- **대안**: 커스텀 아이콘 세트 사용, 또는 아이콘 없이 타이포그래피로 위계 표현

### 8. 카드 왼쪽 컬러 보더

- **탐지**: `border-left: 3px solid <accent-color>` 패턴
- **문제**: AI 코드 생성기의 대표적 카드 스타일링 습관
- **대안**: 그림자, 배경색 차이, 또는 보더 없이 간격으로 구분

### 9. 제네릭 히어로 카피

- **탐지 패턴**:
  - "Welcome to [X]"
  - "Unlock the power of..."
  - "Your all-in-one solution for..."
  - "Revolutionize your..."
  - "Streamline your workflow"
  - "Supercharge your..."
  - "Next-generation..."
- **문제**: 구체적 가치 제안 없이 범용 마케팅 문구. 신뢰 저하
- **대안**: 제품이 해결하는 구체적 문제를 1문장으로, 수치/사례 포함

### 10. 쿠키커터 섹션 리듬

- **탐지**: Hero 이후 3 features, testimonials, pricing, CTA 순서가 기계적으로 반복
- **문제**: 모든 섹션이 같은 높이, 같은 패딩, 같은 구조. 기계적이고 generic
- **대안**: 섹션마다 다른 레이아웃, 정보 밀도 변화, 스크롤 내러티브 설계

## Hard Rejection 기준 (즉시 탈락)

다음 중 하나라도 해당하면 디자인 전체를 재고해야 한다. AI slop 블랙리스트보다 상위 레벨의 구조적 문제.

1. **제네릭 SaaS 카드 그리드가 첫 화면** — 방문자가 처음 보는 것이 카드 나열이면 브랜드/제품 인상 제로
2. **아름다운 이미지 + 약한 브랜드** — 스톡 사진은 좋은데 이 제품이 뭔지 모르겠음
3. **강한 헤드라인 + 명확한 액션 없음** — "혁신적인 플랫폼"인데 뭘 하라는 건지 불명
4. **텍스트 뒤 복잡한 이미지** — 읽기 어려움. 배경과 전경의 대비 부족
5. **같은 분위기 문장을 섹션마다 반복** — "최고의", "혁신적인", "강력한"이 모든 섹션에
6. **내러티브 없는 캐러셀** — 자동 슬라이드가 돌아가는데 왜 봐야 하는지 이유 없음
7. **레이아웃 대신 카드 스택** — 앱 UI를 카드만 쌓아서 만든 것. 공간 설계가 아닌 나열

## 디자인 품질 리트머스 테스트

디자인 완성 후 7가지 자가 점검. 하나라도 "아니오"면 해당 부분 재작업.

1. 첫 화면에서 브랜드/제품이 즉시 식별되는가?
2. 하나의 강한 시각적 앵커(주인공 요소)가 있는가?
3. 헤드라인만 훑어도 페이지 내용을 이해할 수 있는가?
4. 각 섹션이 하나의 역할만 수행하는가?
5. 카드를 쓴 곳에서 카드가 정말 필요한가? (목록이나 텍스트로 대체 가능하지 않은가?)
6. 모션/애니메이션이 위계나 분위기를 개선하는가? (장식이 아닌가?)
7. 장식적 그림자를 모두 제거해도 프리미엄 느낌이 유지되는가?

## 디자인 원칙

AI 도구로 디자인할 때 지켜야 할 핵심 원칙.

### 빼기가 기본 (Subtraction by Default)

Dieter Rams: "가능한 한 적은 디자인." 요소를 추가하기 전에 "이걸 빼면 무엇이 깨지는가?"를 먼저 질문한다. 깨지는 것이 없으면 빼는 것이 정답.

### 빈 상태는 기능이다

"항목이 없습니다."는 디자인이 아니다. 모든 빈 상태(empty state)에는 세 가지가 있어야 한다:
- **온기** — 차가운 시스템 메시지가 아닌 인간적 톤
- **액션** — 사용자가 다음에 할 수 있는 것
- **컨텍스트** — 왜 비어있는지, 언제 채워지는지

### 엣지 케이스는 사용자 경험이다

47글자 이름, 검색 결과 0건, 네트워크 에러 — 이것들은 "나중에 처리"가 아니라 실제 사용자가 가장 자주 좌절하는 순간이다. 메인 플로우와 동일한 수준으로 설계한다.

### 스쿼트 테스트 (Squint Test)

눈을 가늘게 뜨고 화면을 보았을 때:
- 시각적 위계가 보이는가? (제목이 본문보다 눈에 띄는가?)
- 주요 CTA가 구별되는가?
- 섹션 간 경계가 느껴지는가?

보이지 않으면 색상/크기/무게의 대비가 부족한 것이다.

### 수량 제한 규칙

| 항목 | 한계 | 초과 시 |
|------|------|---------|
| 폰트 패밀리 | 3개 이하 | 통일감 상실, 비전문적 인상 |
| 고유 색상 (gray 제외) | 12개 이하 | 컬러 시스템 부재 신호 |
| heading 레벨 스킵 | 0 | h1 다음 h3은 접근성/SEO 문제 |
| body 본문 font-size | 16px 이상 | 16px 미만은 가독성 저하 |
| 터치 타겟 | 44px 이상 | 모바일 조작 불가 |

### 디자이너 비평 화법

디자인 피드백은 지시형이 아닌 질문형으로 전달한다. 수용도가 높고 의도를 존중한다.

```
"I notice..." — 관찰한 것을 서술
"I wonder..." — 왜 그런 선택인지 질문
"What if..." — 대안을 제안
"I think because..." — 근거를 설명
```

예시:
- (지시형) "가운데 정렬을 좌측으로 바꿔라"
- (질문형) "모든 텍스트가 가운데 정렬인 것이 눈에 띕니다. 좌측 정렬로 바꾸면 읽기 흐름이 더 자연스러워질 수 있을까요? 시선이 왼쪽에서 시작하는 것이 일반적이라서요."

## 신뢰도 기반 탐지 계층

| 계층 | 신뢰도 | 탐지 방법 | 예시 |
|------|--------|----------|------|
| HIGH | 코드 패턴 grep | CSS/JSX 정적 분석 | 보라 그라데이션, `outline: none`, font-size 미달 16px |
| MEDIUM | 패턴 집계 | 비율 계산 | center 정렬 60% 초과, border-radius 균일성 80% 초과 |
| LOW | 시각적 판단 | 스크린샷/렌더링 분석 | 3컬럼 그리드, 섹션 리듬, 전체 인상 |

## 도메인별 적용 가이드

### 웹 프론트엔드 (design-guide-builder, frontend-design)

- 10개 항목 전체 적용
- **Phase 3 금지 패턴 섹션**에 AI slop 블랙리스트를 포함하여 DESIGN_SYSTEM.md에 반영
- 디자인 토큰 생성 시 border-radius 계층, 컬러 팔레트 검증에 활용
- HIGH 신뢰도 항목은 코드 생성 시 자동 회피

### 슬라이드 (slide-reviewer, slide-builder, remotion-slide-builder)

- **특히 주의할 항목**: 1(보라 그라데이션), 2(3컬럼 그리드), 4(가운데 정렬 과다), 5(균일 radius), 7(이모지), 9(제네릭 카피)
- 슬라이드 리뷰 시 AI Slop Score를 별도 채점 항목으로 추가
- 발표 슬라이드의 경우 "제네릭 히어로 카피"를 "제네릭 슬라이드 제목"으로 확장 적용

### 제안서/보고서 (문서 작성 스킬)

- **특히 주의할 항목**: 7(이모지), 9(제네릭 카피), 10(쿠키커터 구조)
- 제안서 문구에서 AI 생성 느낌의 범용 표현 탐지
- 다이어그램/인포그래픽에서 보라 그라데이션, 원형 아이콘 패턴 회피
