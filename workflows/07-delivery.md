# Workflow 07 — 최종 게이트 ④ + 배포 준비

목표: 사용자가 최종 산출물을 실제 앱에서 확인하고, 배포 전 점검을 마친다.

## 사람 게이트 ④ — 최종 PPTX/PDF 게이트 (STOP)

1. 확인 안내:
   ```
   open slides-work/<deck-slug>/dist/deck.pptx   # 파워포인트/Keynote에서 열기
   open slides-work/<deck-slug>/dist/deck.pdf
   ```
2. 함께 제시할 확인 목록:

   **(a) 사실 검수 6항목 (사람만 판정 가능 — 하네스가 대신할 수 없다)**

   | # | 항목 | 확인 방법 |
   |---|---|---|
   | 1 | 메시지 정확성 | 각 장 키 메시지가 실제로 주장하려는 바와 같은가 |
   | 2 | 수치 정확성 | 장표의 모든 수치를 원자료와 1:1 대조 — lint 체크 15는 "출처 표기 존재"만 보고 값의 참·거짓은 못 본다 |
   | 3 | 고객사·인물 실명 | 실명·로고 사용 승인 받았는가, 익명화(A사) 필요한 건은 없는가 |
   | 4 | 브랜드 준수 | design-system.md 밖 요소·금지 표현이 남았는가 (lint 체크 6·20 통과 후 사람 최종) |
   | 5 | 보안 정보 | 아래 3항 민감정보 플래그 해소 |
   | 6 | 흐름 논리 | 처음부터 끝까지 1회 통독 — 장표를 섞어도 말이 되면 spine이 없는 것 |

   2·3번은 **사람 확인 없이 통과 불가**로 취급한다 — Evaluator는 storyline.md ↔
   deck.html 일치만 검증하므로, storyline.md의 수치가 처음부터 틀렸으면 전 단계가
   그 오류를 그대로 통과시킨다.

   **(b) 산출물 확인**
   - **critique.md의 "사람 게이트 확인 항목"** — Evaluator가 채점 보류한 시각 잔차
     (텍스트박스 줄바꿈 차이, 표 테두리 스타일, 색감 인상 등)
   - PPTX에서 텍스트박스를 클릭해 **직접 편집이 되는지** (네이티브 납품 조건)
   - 발표자 노트가 노트 창에 보이는지
   - PDF에서 텍스트 검색(Cmd+F)이 되는지
   - 검증 26의 실제 열람 확인 — 파워포인트/Keynote가 경고 없이 여는지
3. **민감정보 플래그 해소 (안전 STOP 게이트)**: lint 체크 18 또는 Evaluator 프로브
   3의 플래그가 남아 있으면 여기서 항목별로 제시하고 **사용자 명시 확인**을 받는다.
   확인 없이 게이트 통과 불가. "이 수치·연락처·단가를 이 자료에 싣는 것이 맞습니까?"
4. 수정 요청이 나오면 workflows/05의 원칙대로 HTML로 돌아가 수정 → 재변환 → 재검증
   → 게이트 ④ 재제시.

## 배포 안내

게이트 ④ 승인 후:

1. **CTA 최종 점검**: CTA 장표의 다음 행동이 여전히 유효한지 (일정·연락처·링크)
   1회 확인을 권한다.
2. **리드마그넷형 추가 절차**:
   - 배포 채널(랜딩 페이지·뉴스레터·세일즈 메일)별 파일 선택 안내 —
     다운로드 배포는 PDF, 편집 제공은 PPTX.
   - 다운로드 동선(어디서 어떤 대가로 받는가)과 후속 접점(다운로드 후 연락 흐름)
     설계가 storyline.md의 CTA 설계와 일치하는지 확인.
   - **외부 공유물은 배포 전 사람 최종 검토 필수** — 스킬·Evaluator 승인은 내부
     품질 게이트일 뿐, 대외 배포 책임 검토를 대체하지 않는다. 이 사실을 명시적으로
     고지하고 검토 완료 확인을 받는다.
3. **배포 후 측정 준비 (외부 배포 시 안내 — 리드마그넷형은 필수)**

   파일을 첨부로만 보내면 측정이 불가능하다. 배포 전에 아래를 안내한다.

   | 지표 | 확보 방법 |
   |---|---|
   | 열람 여부 | 문서 추적 링크로 배포 (파일 직접 첨부 대신 링크 공유) |
   | 장표별 체류 시간 | 링크 뷰어의 페이지 단위 로그 |
   | 다운로드 발생 | 뷰어의 다운로드 허용/차단 설정 + 이벤트 로그 |
   | CTA 클릭 | CTA 장표 링크에 UTM 파라미터 부여 (`utm_source=deck`, `utm_content=S{번호}`) |
   | 폼 제출 | CTA 랜딩의 폼 완료 이벤트 |
   | 완독률 | 마지막 장 도달 비율 |

   - 도구는 사용자 선택이다(문서 추적 서비스·마케팅 자동화·자체 랜딩 중 무엇이든).
     스킬은 **추적 가능한 상태로 만드는 것**까지만 책임진다 — 링크 배포 형태 권고,
     CTA 링크 UTM 부여, 장표 번호와 이벤트명 매핑.
   - **PDF 안의 링크가 유일한 클릭 경로**다. CTA·부록의 URL이 PDF에서 실제로 클릭되는지
     게이트 ④에서 1회 확인한다(변환 시 텍스트로만 남는 URL은 클릭되지 않는다).
   - 측정 결과는 다음 개정의 입력이다: 체류가 짧은 장표 = 메시지 실패 후보,
     이탈이 몰린 장표 = 구조 문제 후보. 재작업 시 `slides-work/<deck-slug>/`로
     돌아와 storyline.md의 해당 장표부터 고친다.
   - 민감정보 플래그가 있었던 덱은 링크 배포 시 **열람 권한·만료 설정**을 함께 안내한다.

4. **외부 공유 일반 원칙**: 리드마그넷형이 아니어도 자료가 조직 밖으로 나가는
   경우(고객 제안, 컨퍼런스)에는 같은 사람 최종 검토 고지를 적용한다.
5. **HTML 중간 산출물 보존 안내**: `slides-work/<deck-slug>/` 전체(특히 deck.html·
   storyline.md·design-system.md)를 보존하면 이후 수정 시 파이프라인을 재사용할 수
   있다 — "다음 수정은 PPTX가 아니라 여기서 다시 시작하는 것이 빠릅니다."
6. status.md 전 단계 ✅ 처리 + 최종 산출물 경로 요약:

```markdown
## 납품 요약
- PPTX (네이티브 편집 가능): slides-work/<deck-slug>/dist/deck.pptx
- PDF (픽셀 동일 인쇄본):   slides-work/<deck-slug>/dist/deck.pdf
- 검증 보고서:              slides-work/<deck-slug>/dist/verify_report.md
- 재수정 진입점:            slides-work/<deck-slug>/deck.html (+ storyline.md)
```
