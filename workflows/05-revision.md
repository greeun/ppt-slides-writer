# Workflow 05 — 렌더 게이트 ③ + 범위 지정 수정 루프

목표: 사용자가 deck.html을 브라우저로 직접 보고, 피드백을 **범위 지정 수정**으로
반영한다. HTML이 중간 렌더 단계로 존재하는 이유가 이 루프다.

## 사람 게이트 ③ — HTML 렌더 게이트

1. 사용자에게 브라우저 확인을 안내한다:
   ```
   open slides-work/<deck-slug>/deck.html
   ```
   확인 포인트를 함께 제시한다: 전체 흐름, 장표별 밀도, 색·폰트 인상, 시각 요소
   품질, critique.md의 "사람 게이트 확인 항목"(Evaluator가 채점 보류한 시각 잔차).
2. AskUserQuestion: **승인(변환 진행)** / **수정 요청** / **디자인 방향 변경**.

## 범위 지정 수정 루프

사용자 피드백을 받으면:

1. **피드백을 장표 범위로 파싱한다** — "3번 장표 표가 빽빽하다", "5~7장 색이 어둡다"
   → 대상 장표 번호 목록 + 변경 유형(콘텐츠/레이아웃/스타일)으로 정리해 확인받는다.
   모호한 피드백("전체적으로 심심하다")은 장표를 특정하는 후속 질문으로 좁힌다.
   시각화 피드백이 모호하면("차트·도식을 활용해 달라") `references/design-rules.md`
   §9 콘텐츠→시각 유형 매핑 사전을 **제안 카탈로그**로 써서 "S6 before/after → 게이지
   바 대비, S7 비교 → ○△× 매트릭스"처럼 장표별 유형을 표로 제시하고 선택받는다.
   즉석에서 유형을 발명하지 않는다.
   **피드백 전달 규칙**: Generator 파견 프롬프트는 design-system.md 토큰의 의미를
   재정의·확장하지 않는다 — "열세는 경고색으로" 같은 색 의미 지정 금지, "의미 라벨은
   design-system.md §1을 따른다"로 참조만 한다. 오케스트레이터의 즉흥 의미 확장은
   Evaluator C2(의미 라벨 붕괴) FAIL로 되돌아온다.
2. **단일 원천 유지**: 콘텐츠(주장·수치·원고) 변경이면 **storyline.md를 먼저 수정**
   하고 deck.html에 반영한다. 레이아웃·스타일만의 변경은 deck.html만 수정한다.
3. **수정 범위 제한**: 지목된 장표만 고친다. 지목되지 않은 장표를 "같이 개선"하지
   않는다 — 승인된 장표를 흔드는 것은 회귀다. 단, 룰 승격(같은 지적 2회 이상 —
   design-rules.md §8)이 발생하면 규칙화 후 전 장표 일괄 적용을 사용자에게 제안한다.
4. **디자인 토큰 변경 요청 처리(STOP)**: "팔레트를 바꿔 달라", "폰트를 바꿔 달라"는
   범위 지정 수정이 아니라 **게이트 ① 재실행 사안**이다. workflows/02로 돌아가
   design-system.md를 재동결한 뒤 전 장표에 재적용한다.
5. 수정 후 **lint 재실행** (ERROR 0 확인):
   ```bash
   python3 {SKILL_DIR}/scripts/lint_slides.py {WORK_DIR}/deck.html \
       {WORK_DIR}/design-system.md {WORK_DIR}/storyline.md
   ```
6. 수정 장표 목록과 lint 결과를 보고하고 게이트 ③을 다시 제시한다.
7. 승인까지 반복한다. 수정 3회 이상 같은 장표가 반복 지적되면 해당 장표만
   레이아웃 2~3안 샘플링(workflows/02 보조 게이트)으로 전환을 제안한다.

## 변환 후 수정 (게이트 ④ 이후 피드백)

PPTX/PDF 확인 후 수정 요청이 오면 **PPTX를 직접 고치지 않는다** — deck.html(필요 시
storyline.md)을 이 루프로 수정한 뒤 workflows/06 변환을 재실행한다. HTML 중간
산출물이 보존되는 한 재변환 비용은 낮다. 사용자가 PPTX에서 직접 편집하는 것은
납품 후 자유이나, 스킬 파이프라인 안에서의 수정 원천은 항상 HTML이다.

## 완료 조건

- 게이트 ③ 승인 + lint ERROR 0 → workflows/06-conversion.md.
