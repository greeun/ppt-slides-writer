# 구조 규칙 상세 참조

## 카탈로그 (CAT) 규칙

### 구조 규칙

- **위치**: `education/catalogs/CAT-{주제}-{연도}.md` 또는 `CAT-{기관}-{연도}.md`
- **역할**: 여러 CU를 하나의 교육 프로그램으로 묶는 상위 단위
- **콘텐츠 직접 작성 금지**: CU wikilink만 포함 (CU와 같은 원칙)
- **CU 상태 표기**: 기존 CU는 wikilink, 미생성 CU는 상태를 "draft (미생성)"으로 표기

### 명명 규칙

| 패턴 | 용도 | 예시 |
|------|------|------|
| `CAT-{주제}-{연도}` | 주제 중심 범용 카탈로그 | `CAT-AI Driven Developer-2026` |
| `CAT-{기관}-{연도}` | 특정 기관 맞춤 카탈로그 | `CAT-KTDS-2026` |

### CAT에 포함하는 것

| 섹션 | 내용 |
|------|------|
| 과정 목록 | CU wikilink, 시수, 대상, 레벨, 상태 |
| 선택 가이드 | Mermaid flowchart로 대상별/레벨별 경로 |
| 학습 경로 | 선수 과정, 권장 순서, 조합 패턴 |
| 일정 템플릿 | 기간별 배치안 (집중/분산/최소) |
| 납품 이력 | 이 카탈로그로 납품한 실적 |
| 차별화 포인트 | 경쟁 대비 강점 |
| 도구/환경 | 전체 과정 필요 도구 합산 |
| 가격 가이드 | 시수별 단가, 패키지 기준 |
| 커스터마이징 | 교체 가능 CU, 시수 조절 범위 |

### CAT에 포함하지 않는 것

- LO 콘텐츠 (CU를 통해 간접 참조)
- 상세 시간표 (각 CU 내부에 존재)
- 실습 환경 상세 설정 (각 CU 내부에 존재)

## 커리큘럼 필수 규칙

> **커리큘럼은 절대로 콘텐츠를 직접 담지 않는다. LO 링크만 참조한다.**

### 반드시 지켜야 할 것 (2026-05-09 갱신)

1. **LO 먼저 생성**: 커리큘럼 생성 시 필요한 LO가 없으면 먼저 **해당 CU 폴더 안 `los/LO-*.md`** 파일 생성
2. **`[[los/LO-...]]` 형식으로 참조**: 커리큘럼의 LO 구성 테이블에는 상대 경로 wikilink 사용 (모호 방지)
3. **양방향 링크**: 생성된 LO의 "사용된 커리큘럼" 섹션에 커리큘럼 링크 추가
4. **재사용 금지, 복사 후 수정**: 다른 CU의 동일/유사 주제 LO가 있으면 **복사 후 해당 CU 시나리오에 맞게 수정**. wikilink로 다른 CU의 LO를 가리키지 않는다
5. **vault 루트 `los/`는 아카이브**: 신규 LO 생성 금지. 과거 자료를 참고용으로 두되, 사용 시 본 CU 폴더로 복사 후 갱신

### 금지 사항

| 금지 | 예시 | 올바른 방법 |
|------|------|------------|
| 커리큘럼에 코드 블록 | CU 파일에 Python 코드 | LO 파일에 작성 후 링크 |
| 커리큘럼에 상세 설명 | CU 파일에 이론 설명 | LO 파일에 작성 후 링크 |
| 커리큘럼에 실습 단계 | CU 파일에 Step 1, 2, 3 | LO 파일에 작성 후 링크 |
| LO 없이 커리큘럼만 생성 | LO 링크 없는 CU | LO 먼저 생성 후 CU 작성 |

### 올바른 커리큘럼 구조 예시

```markdown
## LO 구성

| 순서 | LO | 필수 | 환경 | 내용 요약 | 권장 시간 |
|:----:|-----|:----:|------|----------|----------|
| 1 | [[los/LO-주제A]] | O | 이론 | 개요, 개념 설명 | 40분 |
| 2 | [[los/LO-주제B]] | O | Colab | 설치, 실습 | 50분 |
| 3 | [[los/LO-주제C]] |  | Docker | 심화 실습 | 60분 |
```

## CU 구조

### 납품 CU (`deliveries/CU-주제-기관/`)

기관이 확정된 납품 건. LO 목록, 시간표, CU 활동, 환경 설정을 포함.

```markdown
## LO 구성

| 순서 | LO | 필수 | 의존성 | 내용 요약 |
|------|-----|:----:|--------|----------|
| 1 | [[LO-...]] | O | - | ... |
| 2 | [[LO-...]] |  | LO-1 | ... |

## 운영 가이드

| 구성 | LO | 권장 시간 |
|------|-----|----------|
| 최소 | 1, 2, 5 | 4시간 |
| 표준 | 1~5 | 6~7시간 |
```

### Draft CU (`drafts/CU-주제/`)

미납품 설계안. 기관 확정 시 deliveries/로 이동.

```markdown
## 강의 개요

**강의명 (공식 타이틀)**

> 부제/캐치프레이즈

### 교육 목표
1. (측정 가능한 목표 4개)

### 교육 대상
| 추천 대상 | 경력 | 사전 지식 | 준비물 |

### 교육 특징
- 차별점 3~4개 (볼드 키워드)

### 교육 내용
| 주제 | 시간 | 주요 학습 내용 (3~4개) |

### 기대 효과
| 역량 | 설명 |

### 강사 소개
| 이름 | 소속 | 전문 분야 | 주요 경력 |

## 기반 커리큘럼 및 운영 설계

| 항목 | 내용 |
|------|------|
| **기반** | [[CU-...]] |
| **변형 사유** | 실습 비중 60% 요청 |
| **총 시간** | 8시간 |
| **이론/실습** | 40% / 60% |

## 사용 LO 및 CU 활동

| 순서 | LO / 활동 | 유형 | 시간 | 비고 |
|:----:|-----------|------|------|------|
| 1 | 오프닝 | CU 활동 | 10분 |  |
| 2 | [[LO-...]] | LO | 50분 |  |
| 3 | 프로젝트 실습 | CU 활동 | 60분 | 커리큘럼에 없는 활동 |
```

### CU 활동 (CU에 직접 기술)

LO로 만들지 않는 과정 종속 활동:
- **오프닝**: 자기소개, 과정 안내, 프로젝트 소개
- **프로젝트 실습**: 진행 방법, 체크포인트, 주의사항 포함
- **클로징**: 핵심 정리, Q&A, 실무 도입 팁

## CU 폴더 구조

자료가 있는 CU는 폴더로 승격하고, 모든 관련 자료를 내부에 배치한다.

CU frontmatter에 `slug` 필드(영문 kebab-case) 필수. lab/remotion 이름의 기반이 된다.

### 폴더 내부 구조

| 하위 경로 | 용도 | gitignore |
|----------|------|-----------|
| `CU-{주제}.md` | 커리큘럼 본문 | - |
| `slides/` | 슬라이드 (YAML/MD/Quarto) | - |
| `slides-slidev/` | Slidev 프로젝트 | - |
| `{slug}-guide.md` | 강사가이드 | - |
| `labs/` | 실습 레포 (독립 git clone) | gitignore |
| `remotion/` | Remotion 프로젝트 | gitignore |
| `archive/` | 아카이브 자료 | - |

### lab 명명 규칙

| 유형 | 패턴 | 예시 |
|------|------|------|
| 표준 | `{slug}-{용도}` | `jenkins-cicd-starter` |
| 커스텀 | `{slug}-{용도}-{기관}-{YYMMDD}` | `jenkins-cicd-starter-kosta-250301` |

용도 예시: starter, solution, demo, sandbox 등 자유

## Quality Checklist

### 카탈로그 (CAT-)
- [ ] `education/catalogs/CAT-{이름}.md` 형식으로 생성
- [ ] frontmatter: created, updated, tags, status, client, period, version
- [ ] 과정 목록: 모든 CU가 wikilink로 연결
- [ ] 선택 가이드: Mermaid flowchart 포함
- [ ] 학습 경로: 선수 과정 관계 명시
- [ ] 일정 템플릿: 최소 2가지 편성안
- [ ] 도구/환경: 전체 과정 필요 도구 합산
- [ ] 커스터마이징: 교체/조절 가능 옵션 명시

### 연구 (RE-)
- [ ] `Research/RE-제목.md` 형식으로 생성
- [ ] 개요: 주제, 목표, 예상 결과물
- [ ] 배경 및 동기: 문제 정의, 기존 한계
- [ ] 연구 설계: 접근 방법, 핵심 가설
- [ ] 관련 문헌(LIT-) 링크 연결
- [ ] type 필드 (research/patent/design/experiment)

### 문헌 (LIT-)
- [ ] `literature/LIT-제목.md` 형식으로 생성
- [ ] 출처 정보: 제목, 저자, 링크 완비
- [ ] 요약: 한 줄 요약, 핵심 주장
- [ ] 인사이트: 내 해석, 적용 아이디어
- [ ] type 필드 (paper/book/article/course)

### CU (납품 건)
- [ ] `deliveries/CU-주제-기관/` 또는 `drafts/CU-주제/` 형식으로 생성
- [ ] 강의 개요 완비 (강의명, 교육 목표, 대상, 특징, 내용, 기대 효과)
- [ ] 기반 커리큘럼 및 운영 설계 통합
- [ ] 사용 LO 및 CU 활동 표: 유형, 시간, 비고
- [ ] 구체적 시간표 포함
- [ ] CU 활동 상세 (오프닝, 프로젝트 실습, 클로징)
- [ ] 환경 설정 (강사/수강생 준비)

### LO (LO-)
- [ ] `los/LO-제목.md` 형식으로 생성
- [ ] slug 필드 (영문 kebab-case)
- [ ] duration: 25M (기본값)
- [ ] 학습 목표가 측정 가능한 형태
- [ ] type 필드 (theory/hands-on)

## Research vs Literature 역할 분리

| 구분 | Research (RE-) | Literature (LIT-) |
|------|----------------|-------------------|
| **성격** | 내가 만드는 것 | 남의 것을 정리 |
| **예시** | 특허, 설계, 실험 | 논문 리뷰, 책 요약, 스터디 |
| **상태** | 진행/완료/중단 | 읽음/미읽음 |
| **결과물** | Notes, 특허, 코드 | 인사이트를 Research/Notes로 |
| **교육 연계** | 연구 결과를 LO로 발전 가능 | 참고 자료로 활용 |

## 웹 리서치 규칙

LO 콘텐츠 작성 시 반드시 웹 검색으로 최신 정보를 확인하고 출처를 명시.

### 필수 검색 항목

| 항목 | 검색 내용 | 기록 위치 |
|------|----------|----------|
| 공식 문서 | 도구/라이브러리 공식 문서 URL | LO 참고 자료 |
| 최신 버전 | 현재 버전, 변경 사항 | LO 이론 내용 |
| 설치 방법 | 플랫폼별 설치 명령 | LO 실습 단계 |
| 알려진 이슈 | 호환성, 제한 사항 | LO 체크포인트 |

### 품질 기준

- [ ] 모든 기술 정보에 공식 문서 링크 포함
- [ ] 설치/실행 코드는 공식 문서 기반
- [ ] 버전 정보 명시 (예: `vllm==0.6.3`)
- [ ] 최소 3개 이상 신뢰할 수 있는 출처

## 팩트체크 규칙

LO에 포함되는 모든 사실 정보는 아래 규칙을 따른다.

### AI 모델명, 버전

- **모델명은 반드시 웹 검색으로 현재 공식 명칭을 확인** (세대 명칭을 추측으로 기재하지 않고 작성 시점 공식 라인업을 확인한다. 예: 2026-08 확인 기준 현행 라인업은 Claude 5 패밀리 — Fable 5/Opus 5/Sonnet 5 — 와 Haiku 4.5)
- 모델 패밀리(GPT, Claude, Gemini 등)의 최신 라인업을 공식 사이트에서 확인
- 벤치마크 점수는 공식 발표 또는 신뢰할 수 있는 리더보드(예: SWE-bench, MMLU) 기준, **출처 URL 필수**

### 정량 수치, 통계

- 시장 규모, 성장률, 도입 비율 등 **정량 수치에는 반드시 출처 표기**
- 출처를 찾을 수 없는 수치는 **"(추정)"을 명시**하거나 삭제
- 보고서 출처는 기관명 + 연도 포함 (예: "McKinsey, 2025")

### 기업, 제품 사례

- **기업을 성공 사례로 인용할 때 현재 상태를 반드시 검증**
  - 매출 감소, 대규모 구조조정, 서비스 종료 등이 발생한 기업은 성공 사례로 부적절
  - 최소 최근 6개월 이내 뉴스/실적을 확인
- 스타트업 사례는 변동성이 크므로 "교육적 예시"임을 명시하거나, 대형/안정적 사례 우선 사용

### 가격, 기능 정보

- AI 제품 가격과 기능은 변동이 잦으므로 **작성 시점 기준임을 명시**
- 무료/유료 구분, 기능 제한 사항은 공식 사이트에서 확인
