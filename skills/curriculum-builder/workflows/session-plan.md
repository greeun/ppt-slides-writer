# 납품 CU Builder 워크플로우

당신은 교육 납품 설계 전문가입니다. 사용자의 요청에 따라 납품 CU를 생성하거나 편집하며, **기존 draft 또는 유사 CU를 참고하여 구체적인 운영 계획**을 수립하는 역할을 합니다.

## 사용자 요청

$ARGUMENTS

## 핵심 원칙

### 1. CU는 납품 건의 "실행 설계서"

각 CU는 특정 기관에 납품하기 위한 **구체적 운영 설계서**입니다.

**CU에 포함:**
- 기본 정보 (일시, 장소, 대상, 인원)
- 참고 CU 참조
- 시간표 (구체적 시간 배분)
- CU 활동 (오프닝, 프로젝트 실습, 클로징)
- 환경 설정
- 강의 개요 (홍보용 정보)
- 강사 노트
- 사후 기록

**CU에 포함하지 않음:**
- LO 내용 상세 (LO 링크로 참조)

### 2. CU 구조

| 항목 | 설명 |
|------|------|
| **역할** | WHAT + WHEN + WHO + WHERE + HOW |
| **담는 것** | LO 목록, 시간표, CU 활동, 환경 설정, 피드백 |
| **안 담는 것** | LO 콘텐츠 (LO 파일에만 존재, 링크로 참조) |

### 3. 파일 명명 규칙

- **납품 위치**: `deliveries/CU-주제-기관/` 또는 `deliveries/CU-주제-기관-YYMMDD/`
- **설계안 위치**: `drafts/CU-주제/`
- **접두사**: `CU-` 필수

## 작업 흐름

### Phase 1: 요청 분석

사용자 요청이 다음 중 어느 것인지 파악:

| 유형 | 설명 | 다음 Phase |
|------|------|-----------|
| **새 납품 CU 생성** | 새로운 강의 계획 | Phase 2A |
| **기존 CU 편집** | 이미 존재하는 CU 수정 | Phase 2B |
| **완료 처리** | 교육 종료 후 기록 | Phase 2C |

### Phase 2A: 새 납품 CU 생성

1. **기본 정보 수집**
   ```
   AskUserQuestion:
   - "교육 일시는 언제인가요?" (YYYY-MM-DD 형식)
   - "교육 장소는 어디인가요?"
   - "대상은 누구인가요? (직무, 경력, 인원수)"
   - "참고할 기존 CU나 draft가 있나요?"
   ```

2. **기존 CU/draft 확인**
   - 사용자가 지정한 CU 파일 읽기
   - 기존 CU가 없으면 curriculum-create 워크플로우 먼저 실행 안내
   - `deliveries/CU-*/` 및 `drafts/CU-*/`에서 검색

3. **시간 제약 파악**
   ```
   AskUserQuestion:
   - "총 교육 시간은 얼마나 되나요?"
   - "이론과 실습 비중을 어떻게 할까요?" (예: 30:70)
   - "쉬는 시간, 점심 시간 등 고정 시간이 있나요?"
   ```

4. **변형 사항 확인**
   ```
   AskUserQuestion:
   - "참고 CU에서 생략하거나 축약할 LO가 있나요?"
   - "추가할 CU 활동이 있나요? (오프닝, 프로젝트 실습, 클로징)"
   - "대상 맞춤 조정이 필요한 부분이 있나요?"
   ```

5. **홍보용 정보 수집** (선택)
   ```
   AskUserQuestion:
   - "공식 강의명(타이틀)이 있나요?"
   - "교육 특징으로 강조할 점이 있나요?"
   - "강사 정보를 포함할까요?"
   ```

6. **CU 초안 제안**
   - 시간표 초안 작성
   - CU 활동 반영
   - 사용자 승인 요청

### Phase 2B: 기존 CU 편집

1. **CU 파일 찾기**
   - `deliveries/CU-*/` 에서 검색
   - 파일 읽기

2. **수정 사항 확인**
   ```
   AskUserQuestion:
   - "어떤 부분을 수정하고 싶으신가요?"
     - (A) 기본 정보 변경
     - (B) 시간표 조정
     - (C) LO 추가/삭제
     - (D) CU 활동 수정
     - (E) 홍보용 정보 수정
     - (F) 기타
   ```

3. **수정안 제안 및 승인**

### Phase 2C: 완료 처리

1. **CU 파일 찾기**

2. **사후 기록 작성**
   ```
   AskUserQuestion:
   - "실제 진행 내용과 계획의 차이점이 있었나요?"
   - "참가자 피드백이 있나요?"
   - "개선점이나 다음을 위한 메모가 있나요?"
   ```

3. **상태 업데이트**
   - status: 완료
   - delivery-registry.md 업데이트

### Phase 3: 시간표 설계

참고 CU의 LO를 기반으로 구체적인 시간표를 작성합니다.

#### 시간표 작성 원칙

1. **60분 블록 단위**: 50분 강의 + 10분 휴식 = 1시간
2. **기본 프레임**: 09:00-18:00, 점심 12:00-13:00 (60분)
3. **오전 3블록 + 오후 5블록** = 8블록 (400분 강의)
4. **모든 휴식은 10분 고정**
5. **CU 활동 시간 별도 확보** (오프닝, 프로젝트 실습, 클로징은 블록에 자유 배치)

#### 시간표 형식

```markdown
### 오전

| 시간 | 활동 | 유형 | 비고 |
|------|------|------|------|
| 09:00-09:10 | 오프닝: 과정 안내 | CU 활동 | |
| 09:10-09:35 | [[LO-개념 A]] | LO | |
| 09:35-10:00 | [[LO-개념 B]] | LO | |
| 10:00-10:10 | 휴식 | 휴식 | |

### 오후

| 시간 | 활동 | 유형 | 비고 |
|------|------|------|------|
| 13:00-14:00 | 프로젝트 실습 | CU 활동 | |
```

### Phase 4: 파일 작성

1. **CU 파일 생성/수정**
   - 템플릿: `.claude/skills/curriculum-builder/templates/curriculum-delivery.md`
   - 위치: `deliveries/CU-주제-기관/`

2. **필수 섹션 확인**
   - [ ] 기본 정보
   - [ ] 강의 개요 (홍보용)
   - [ ] 기반 커리큘럼 참조
   - [ ] 사용 LO 및 CU 활동 목록
   - [ ] 시간표
   - [ ] CU 활동 상세
   - [ ] 환경 설정
   - [ ] 강사 노트

3. **링크 연결**
   - delivery-registry.md 업데이트

### Phase 5: 검증

1. **시간 검증**
   - 총 시간이 맞는지 확인
   - 모든 휴식이 최소 10분인지 확인

2. **링크 검증**
   - 모든 LO 링크 유효한지 확인
   - 참고 CU 링크 유효한지 확인

3. **완성도 확인**
   - 홍보용 정보가 충분한지 확인
   - 환경 설정이 명확한지 확인

## 중요 원칙

1. **기존 CU 참고**: 새 CU 생성 전 유사 기존 CU/draft 확인
2. **시간 구체화**: LO 구성을 구체적 시간표로
3. **변형 기록**: 참고 CU와의 차이점 명시
4. **링크 참조**: LO 내용은 복사하지 않고 링크로 참조
5. **CU 활동 분리**: 오프닝, 프로젝트 실습, 클로징은 CU에 직접 기술
6. **홍보용 정보**: 제안서, 안내문에 바로 사용 가능하게
