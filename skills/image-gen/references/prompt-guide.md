# 프롬프트 작성 가이드

이 스킬의 핵심. 좋은 프롬프트가 좋은 이미지를 만든다.

## 프롬프트 형식

3-섹션 구조나 고정 템플릿 없이 **자연어 한 덩어리**로 작성한다.
웹 Gemini에 말하듯 자연스럽게, 하지만 극도로 구체적으로.

```
한 장의 16:9 가로형 인포그래픽 이미지를 만들어줘.

{이미지의 전체 구성을 자연어로 설명}
{각 영역의 배경색, 내부 요소, 텍스트, 아이콘을 구체적으로}
{영역 간 연결선, 화살표, 데이터 흐름}
{강조 포인트}
{제안서/보고서 삽화인 경우에만: 하단 Key Takeaway 바}

이 이미지에 표시하지 말 것: {메타 정보가 있으면 명시}

스타일: {톤 가이드에서 가져온 핵심 지시}
```

## 프롬프트 작성 원칙

### 1. 영역별로 구체적으로 기술한다

각 영역에 대해 다음을 명시:
- 배경색 (#hex 코드 — 톤 가이드에서 가져옴)
- 헤더/라벨 텍스트 (실제 들어갈 문구를 따옴표로)
- 아이콘 종류 (구체적 형태: "3층 원통 아이콘", "분기 화살표 아이콘")
- 내부 텍스트 (제목, 부제, 키워드, 수치)
- 느낌/분위기 (선택: "역동적, 성장하는 느낌" 등)

```
예시 — 나쁜 프롬프트:
"왼쪽에 현재 상태, 오른쪽에 제안 솔루션을 배치"

예시 — 좋은 프롬프트:
"좌측 패널 (회색 배경 #F2F2F2, 테두리 #5A5A5A):
  헤더 바 'DX (Digital Transformation)' 진한 회색 배경에 흰 글씨.
  내부에 서류/모니터 아이콘과 '업무 프로세스 디지털화' 텍스트.
  큰 숫자 '$12.9B' (2024), 작은 텍스트 'Gartner, 2024'.
  전체적으로 정적이고 낡은 느낌."
```

### 2. 화살표와 연결선을 별도로 기술한다

```
"좌측 패널에서 우측 패널로 회색에서 녹색으로 그라데이션 큰 화살표.
 화살표 위에 '패러다임 전환' 텍스트.
 화살표 아래에 '버티컬 AI, VC 투자 역전 ($3.2B > $2.7B)'"
```

### 3. 맥락을 프롬프트에 녹인다

AI가 기술적 맥락을 이해해야 올바른 구도를 잡는다.
이미지에 표시되지 않는 배경 지식도 프롬프트 안에 자연스럽게 풀어 쓴다.

```
"이 이미지는 정부 R&D 과제 제안서의 기술 아키텍처 설명 삽화임.
 심사위원이 이 한 장으로 시스템 전체 구조를 파악해야 함.
 tree-sitter는 소스코드를 AST로 파싱하는 도구이고,
 SurrealDB는 그래프 데이터베이스로 코드 간 관계를 저장함.
 이 둘의 연결이 시스템의 핵심이므로 시각적으로 가장 강조되어야 함.
 (위 설명은 이미지에 텍스트로 넣지 말 것 — 구도 결정용 참고 정보)"
```

### 4. 하단 핵심 메시지 바 (선택)

이미지 하단에 핵심 메시지를 한 줄로 요약하는 바를 배치하면 가독성이 올라간다.

**주의: 프롬프트에 "Key Takeaway"라는 텍스트를 쓰면 Gemini가 그 라벨을 이미지 안에 그대로 렌더링한다.**
프롬프트에서는 "하단 요약 바", "하단 메시지 바" 등으로 표현하고,
"Key Takeaway"라는 단어 자체는 프롬프트에 절대 포함하지 않는다.

```
"하단 요약 바 (#D5E8D4 배경, 전체 폭):
 '축적된 조직 지식 = 전환 장벽 — 경쟁사가 복제 불가한 구조적 진입장벽'"
```

### 5. "표시하지 말 것"은 명시적으로

이미지에 렌더링하면 안 되는 메타 정보가 있으면 프롬프트 끝에 명시:

```
"이미지에 표시하지 말 것:
 - 그림 번호 ([그림 2-3] 등은 본문에서 처리)
 - 퍼센트(%) 수치가 레이아웃 비율이 아닌 콘텐츠로 혼동되지 않도록 주의
 - 워터마크 없음"
```

## 시각 블록 참고

프롬프트 구성 시 `references/visual-blocks.md`를 참고할 수 있다.
카드, 타임라인, 화살표 플로우, 계층 박스, 존 패널, UI 목업 등
자주 쓰이는 시각 블록의 카탈로그가 정리되어 있다.
블록은 자유롭게 조합하거나, 카탈로그에 없는 새로운 구성도 가능하다.
