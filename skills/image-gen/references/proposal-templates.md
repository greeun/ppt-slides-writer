## 검증된 구도 패턴 (2026-03 특허기반 사업화 R&D 제안서에서 검증)

### 1. 제품 대시보드 UI

**용도**: 제안서 "대상 제품 사진" 란

**구도 (밀도 높은 대시보드)**:
- 상단 헤더: 제품 로고 + 탭 네비 + 알림 + 아바타 + 프로젝트 선택
- 좌측 사이드바: 프로젝트 리스트 + 원형 진행률
- KPI 카드 4개 (수치 + 프로그래스바 + 전주 대비 변화율)
- 중단 좌: 핵심 시각화 (노드 그래프, 차트 등)
- 중단 우상: 보조 시각화 (히트맵, 매트릭스)
- 중단 우하: 테이블 (최근 활동, 이력)
- 하단: 상태바 (핵심 수치 요약)

**핵심 포인트**:
- Datadog, Linear, Vercel 수준의 정보 밀도
- 빈 영역 없이 꽉 차야 "실제 제품"처럼 보임
- 상태 뱃지(완료/경고/위험)로 시각적 다양성

### 2. 상세 에디터 UI

**용도**: 제안서 "대상 제품 사진" 두 번째 이미지

**구도 (3패널 에디터)**:
- 좌(25%): 트리 네비게이션 (계층 구조, 들여쓰기, 상태 아이콘)
- 중앙(50%): 선택 항목 상세 (제목 + 뱃지 + 메타데이터 + 본문 + 관련 정보)
- 우(25%): 컨텍스트 패널 (차트/통계 + 입력 필드 + 관련 항목 목록)
- 하단: 전체 요약 상태바

**핵심 포인트**:
- Notion+Linear 스타일의 에디터 UI
- 트리에서 선택한 항목이 중앙에 상세하게 보이는 구조
- 코드 하이라이팅이 들어가면 기술 제품 느낌 강화

### 3. 시스템 블록 다이어그램 (아키텍처)

**용도**: 제안서 "세부 도면" 란

**구도 (수직 4레이어)**:
```
[레이어 1 - 클라이언트] 연한 초록 배경
  블록 3~4개 수평: Web | CLI | API | 모바일
  프로토콜 표시: HTTPS, gRPC, MCP

[API Gateway] 네이비 배경 — 인증, Rate Limit, 로드밸런싱

[레이어 2 - 엔진/서비스] 연한 파랑 배경
  블록 3~4개 수평, 각 블록 안에 서브 컴포넌트 4개
  핵심 블록은 크게, 별 아이콘으로 강조

[레이어 3 - 데이터] 파랑 그라데이션
  DB 블록(원통 아이콘) + 캐시 + 스토리지

[레이어 4 - 인프라] 회색 배경
  K8s | CI/CD | 모니터링 | CDN
```

**핵심 포인트**:
- 레이어 간 화살표에 프로토콜/API 이름 표시
- 특허 기술은 별 아이콘 + 특허번호로 강조
- 서브 컴포넌트까지 보여야 "구체적인 설계"로 인정받음

### 4. 배포 아키텍처 (인프라)

**용도**: 제안서 "세부 도면" 두 번째 이미지, SaaS 운영 역량 증명

**구도 (좌에서 우로 흐름)**:
```
[사용자] → [CDN] → [WAF] → [Load Balancer]
                                    ↓
              [Kubernetes Cluster — 큰 테두리]
              ┌─────────────────────────────────┐
              │ API Pods │ Worker Pods │ MCP Pods│
              │ Ingress  │ Service Mesh          │
              └─────────────────────────────────┘
                     ↓              ↓
              [DB 클러스터]    [모니터링]
              Primary+Replica  Prometheus
              Redis 캐시       Grafana
              S3 스토리지      Sentry, ELK
                                    ↓
              [CI/CD 파이프라인 — 하단 수평]
              GitHub → Actions → 테스트 → 스테이징 → 프로덕션
```

**핵심 포인트**:
- SLA 수치 명시 (99.9%, 자동 스케일링 범위)
- Blue-Green 무중단 배포 등 운영 키워드
- 서비스별 실제 도구명(Prometheus, Grafana, Istio 등) 표기

### 5. 데이터 흐름도

**용도**: 특허 기술 메커니즘 설명

**구도 (좌 입력 → 중앙 처리 → 우 출력)**:
```
[입력 소스]     [처리 레이어 — 세로 3단]     [출력]
  아이콘 →      상단: 1차 처리 (연한 색)     → 결과
  아이콘 →      중단: 2차 처리 (중간 색)     박스
  아이콘 →      하단: 3차 처리 (진한 색)
                    ↕ 승격 조건 텍스트
```

**핵심 포인트**:
- 계층 간 승격/이동 조건을 화살표 옆에 텍스트로
- 색상 그라데이션으로 깊이감 표현
- 수식이 있으면 우측에 작게 표시

## 공통 스타일 규칙

- **배경**: 밝은 회색(#F8FAFC), 카드 흰색(#FFFFFF)
- **테두리**: 연한 회색(#E2E8F0), 둥근 모서리 12px
- **그림자**: 미세한 그림자 (depth 느낌)
- **텍스트**: 한국어 중심, 핵심 기술 용어만 영문 병기
- **색상**: 프로젝트 톤 가이드 따름 (없으면 보수적 파랑/회색 계열)
- **강조**: 특허/핵심 기술은 별 아이콘 + 진한 배경 + 번호 표기
- **상태**: 초록(완료) / 파랑(진행) / 노랑(주의) / 빨강(경고) 4색 체계

## HTML 목업 → 스크린샷 파이프라인 (UI 이미지 한정)

AI 생성 이미지보다 HTML 목업 스크린샷이 훨씬 실제 제품처럼 보임.
1. image-gen으로 구도/컨셉 확인
2. 에이전트에게 단일 HTML 파일 제작 의뢰 (design-tokens.css 기반, 1920x1080, Pretendard)
3. `npx playwright screenshot --viewport-size="1920,1080" "file:///path.html" "output.png"`
