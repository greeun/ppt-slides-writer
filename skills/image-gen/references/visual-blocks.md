# 시각 어휘 (Visual Vocabulary)

이미지 구성 시 자유롭게 조합할 수 있는 빌딩 블록 목록.
**하나만 쓸 수도, 여러 개를 조합할 수도 있다.** 내용이 구조를 결정한다.

## 블록 카탈로그

### 정보 표현 블록

| 블록 | 설명 | 적합한 상황 |
|------|------|------------|
| **카드** | 둥근 모서리 박스에 아이콘+제목+설명. 2~6개 그리드 | 개념 나열, 특징 소개, 카테고리 구분 |
| **숫자 강조** | 큰 숫자 + 작은 레이블 + 미니 그래프(선택) | KPI, 성과 지표, 통계 인용 |
| **비교 컬럼** | 좌우 또는 상하 분할, 색상으로 구분 | Before/After, 문제/해법, 경쟁 비교 |
| **계층 박스** | 중첩되거나 쌓인 박스, 크기로 위계 표현 | 아키텍처, 기술 스택, 조직 구조 |
| **타임라인 바** | 수평/수직 진행선 + 마일스톤 포인트 | 로드맵, 일정, 발전 단계 |

### 관계 표현 블록

| 블록 | 설명 | 적합한 상황 |
|------|------|------------|
| **화살표 플로우** | 단계 박스를 화살표로 연결 (직선/곡선) | 프로세스, 워크플로우, 파이프라인 |
| **수렴/분기** | 여러 요소가 하나로 모이거나 하나에서 퍼짐 | 근본 원인, 효과 확산, 통합 |
| **방사형** | 중앙에서 바깥으로 뻗는 구조 | 핵심 개념과 파생 요소 |
| **순환 루프** | 원형 또는 곡선 화살표로 반복 표현 | 피드백 루프, 반복 프로세스 |
| **점선 연결** | 약한 관계, 외부 의존, 선택적 연결 | 외부 서비스, 옵션, 참조 |

### 강조 블록

| 블록 | 설명 | 적합한 상황 |
|------|------|------------|
| **배지/뱃지** | 진한 배경 + 흰 글씨, 시선 집중 | 핵심 결론, 주요 메시지, CTA |
| **아이콘/일러스트** | 구체적 시각 메타포 (로봇팔, 깨진 퍼즐 등) | 추상 개념의 직관적 전달 |
| **하이라이트 영역** | 배경색 변화로 영역 구분 | 관련 블록 그룹핑, 주목 영역 |
| **체크/엑스 마크** | ✓/✗ 로 성공/실패 표시 | 비교, 체크리스트, 요건 충족 |
| **라벨/태그** | 작은 텍스트 칩 | 기술명, 카테고리, 출처 표기 |

### 복합 구성 블록

| 블록 | 설명 | 적합한 상황 |
|------|------|------------|
| **존(Zone) 패널** | 둥근 모서리 큰 박스로 영역 분할, 상단에 라벨 배지. 존별 배경색 구분 | 기관별 역할 분담, 시스템 영역 구분, 연구 추진체계 |
| **UI 목업 윈도우** | 브라우저/앱 윈도우 프레임(타이틀바+닫기버튼) 안에 스크린샷 형태 콘텐츠 | 제품 데모 화면, 대시보드 미리보기, 기능 시연 |
| **코드 스니펫** | 어두운 배경(#1E1E1E)에 구문 강조된 코드 3~5줄, 모노스페이스 서체 | 기술 구현 예시, API 호출 샘플, 알고리즘 설명 |
| **기술 로고 배치** | 실제 기술 로고 형태(언어, 프레임워크, DB 등)를 적절한 위치에 배치 | 기술 스택 표현, 도구 연동 관계, 파트너 기술 |
| **일러스트 씬** | 플랫 스타일 사람+장비+환경이 어우러진 작은 장면 (삽화 느낌) | 존 내부 분위기 전달, 사용 시나리오, 역할 표현 |
| **데이터 흐름 파이프** | 존 사이를 연결하는 굵은 화살표(3~4px) + 라벨, 데이터 변환 표현 | 시스템 간 데이터 이동, API 연동, 파이프라인 |
| **지표 대시보드** | 미니 그래프(막대/선/도넛) + 수치가 포함된 소형 패널 | 성능 지표, 모니터링 화면, KPI 요약 |

## 조합 예시

블록은 자유롭게 조합한다. 아래는 영감 제공용이지 따라야 할 구조가 아님:

```
비교 컬럼(문제 vs 해법) + 카드(4요소) + 화살표 플로우(처리 과정)
→ 상단에서 문제/해법 대비, 중간에 핵심 요소 카드, 하단에 실제 흐름
```

```
타임라인 바(3개년) + 숫자 강조(목표치) + 배지(현재 단계)
→ 진행선 위에 마일스톤, 주요 수치 강조, 현재 위치 표시
```

```
계층 박스(3레이어) + 화살표 플로우(데이터 흐름) + 라벨(기술 스택)
→ 시스템 구조도에 데이터 흐름과 기술명 표기
```

```
방사형(중심 개념) + 카드(주변 요소) + 점선 연결(외부 연동)
→ 핵심 기능 중심으로 관련 모듈 배치
```

## 색상 원칙

> **3색 규칙**: 주색 1 + 보조 1 + 강조 1. 나머지는 명도/채도 변화로 해결한다.

- **주색**: 전체 톤을 결정하는 색 (예: 짙은 파랑 #2D519F)
- **보조색**: 주색의 밝은/어두운 변형 또는 회색 계열
- **강조색**: 핵심 수치, 결론, CTA에만 사용. 남발하면 강조가 아님
- **금지**: 무지개 팔레트, 카드마다 다른 색, 네온 3색 이상 동시 사용
- 색상이 많아질수록 유치해진다. **절제가 고급스러움**이다

프로젝트별 톤 가이드에서 hex 코드를 가져오되, 위 원칙을 벗어나지 않는다.

## 구성 원칙

1. **내용이 구조를 결정한다** — 블록을 먼저 고르지 말고, 전달할 메시지를 먼저 파악
2. **시선 흐름을 설계한다** — 가장 중요한 것 → 보조 정보 → 세부사항 순서
3. **하나의 이미지, 하나의 메시지** — 너무 많은 블록을 욱여넣지 않는다 (단, 고밀도 기술 다이어그램은 예외: 한 장에 시스템 전체를 담는 것이 목적)
4. **일러스트는 구체적으로** — "적절한 아이콘" ❌ → "로봇팔이 아래를 가리키는 그림" ✅
5. **디테일에 창의성을** — 배경(반투명 패턴, 미세 텍스처), 아이콘 선택, 여백 활용 등 작은 요소에서 개성을 낸다. 규칙에 없는 시각적 포인트를 자유롭게 시도할 것
6. **고밀도 다이어그램의 존 분할** — 존 분할로 정보를 구조화하면 10개 이상 요소도 가독성을 유지할 수 있다. 존별 배경색으로 시각적 경계를 만들고, 존 내부는 블록을 자유롭게 조합
