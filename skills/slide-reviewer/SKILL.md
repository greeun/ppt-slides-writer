# Slide Reviewer

Remotion 또는 마크다운 슬라이드를 5개 전문가 페르소나로 리뷰하여 우선순위별 액션 아이템을 도출하는 스킬.

## 핵심 원칙

```
모든 슬라이드 파일을 직접 Read하여 분석한다
코드를 수정하지 않는다 — 리뷰와 제안만 출력한다
5개 페르소나가 독립적으로 평가한 후 통합 액션 아이템으로 정리한다
P0(즉시 수정) > P1(중요) > P2(개선) > P3(선택) 우선순위를 부여한다
```

## 의도 파악

### 필수 확인 사항

| 항목 | 질문 |
|------|------|
| 슬라이드 경로 | Remotion `src/slides/` 또는 마크다운 슬라이드 폴더 위치 |
| 청중 | 발표 대상 (투자자, 경영진, 개발자, 일반 청중 등) |
| 목적 | 발표의 핵심 목적 (투자 유치, 파트너십, 제품 데모, 교육 등) |

### 바로 실행

- 슬라이드 경로가 명확히 지정된 경우
- 방금 slide-builder/remotion-slide-builder로 슬라이드를 완성한 직후

## 워크플로우

### Phase 1: 슬라이드 수집

모든 슬라이드 소스 파일을 Read한다.

```
1. Remotion: src/slides/*/S*.tsx 파일 전체
2. 마크다운: *.md 슬라이드 파일 전체
3. 테마 파일 (theme.ts 또는 CSS)
4. 컴포넌트 파일 (SlideLayout 등 — props 이해용)
```

### Phase 2: 페르소나별 리뷰

5개 페르소나가 독립적으로 평가한다. 각 페르소나의 상세 평가 기준은 `references/personas.md` 참조.

| 페르소나 | 핵심 질문 |
|---------|----------|
| **투자자** | 시장 기회, TAM/SAM/SOM, 경쟁 해자, 매출 전망 근거, 팀 역량 |
| **기술 경영자** | 기술 선택 합리성, 완성도 솔직함, 과장 여부, 아키텍처 타당성 |
| **사업 파트너** | 수익 구조 명확성, 역할 분담, 초기 액션, 리스크 투명성 |
| **디자이너** | 정보 밀도 균일성, subtitle 유무, 여백, 시각 요소 배치, 색상 일관성 |
| **발표자** | 스토리 아크, 핵심 메시지 명확성, 시간 배분, 에너지 유지 |

### Phase 3: 통합 액션 아이템

페르소나별 피드백을 우선순위 테이블로 통합한다.

```markdown
| 우선순위 | 슬라이드 | 문제 | 수정 제안 | 관련 페르소나 |
|---------|---------|------|----------|-------------|
| P0 | S3 | subtitle 누락 | 키 메시지 추가 | 디자이너 |
| P1 | S5 | 매출 근거 부재 | 가정 테이블 추가 | 투자자 |
```

### Phase 4: 자동 수정 (선택)

사용자가 "수정해줘", "적용해줘"라고 하면:
1. P0 항목부터 순서대로 수정
2. 병렬 에이전트로 독립적인 수정 동시 진행
3. 수정 후 TypeScript 타입 체크 실행
4. 수정 결과를 요약 테이블로 보고

## 장표 단위 리뷰 절차

페르소나 리뷰(Phase 2)가 청중 관점의 평가라면, 장표 단위 리뷰는 **장표의 경험 문제**(표현 어색함, 레이아웃 반복, 내용 어려움)를 composition 순서대로 점검하는 절차다. 두 흐름은 충돌하지 않으며, 교육 슬라이드에서는 페르소나 리뷰와 함께 이 절차를 병행한다.

- **문자열 검색 금지**: 장표 경험 문제는 grep으로 잡히지 않는다. composition(상영) 순서대로 정렬한 장표 단위 리뷰 문서를 먼저 작성한 뒤 그 위에서 점검한다.
- **수정 순서**: P0(공통 생성 규칙) → P1(중복 템플릿 제거) → P2(난이도·표현 보강) 순서로 고친다. 리뷰와 수정을 분리하고, 수정 후 대표 스틸을 렌더해 검증한 뒤 PDF로 출력한다.
- **6개 점검 항목**: 표현(포멀 한국어) · 템플릿 반복 · 핵심 메시지 · 난이도(용어 설명) · LO 정합성 · 앞뒤 연결성.

> 상세 절차와 점검 기준은 remotion-slide-builder 스킬의 [`references/review-rules.md`](../remotion-slide-builder/references/review-rules.md)를 참조한다.

## 평가 기준 요약

### 디자인 체크리스트 (모든 슬라이드 공통)

- 모든 SlideLayout에 `subtitle` (키 메시지)이 있는가
- 텍스트가 충분한가 (빈 공간 과다 아닌지) (판정 기준: slide-builder 분량 가이드라인 — 슬라이드당 6줄 이내·불릿 3~5개 — 에 크게 못 미치면 빈 공간 과다)
- 정보가 넘치지 않는가 (과밀 아닌지) (판정 기준: 슬라이드당 6줄·불릿 5개 초과, 또는 remotion 최소 폰트 20px 미만으로 줄여야 들어가면 과밀)
- 시각 요소(차트, 이미지, 테이블, 다이어그램)가 적절히 배치되었는가
- 특수 기호(화살표 등)로 축약하지 않았는가 (볼트 규칙)
- 격식체(합쇼체) 사용 여부

### AI Slop 체크 (슬라이드 특화)

`../../resources/ai-slop-checklist.md` 참조. 슬라이드에서 특히 주의할 항목:

- **보라/인디고 그라데이션** — 배경이나 카드에 indigo-violet 그라데이션 사용 여부
- **3컬럼 대칭 그리드** — 원형 아이콘 + 제목 + 설명 x3 반복 레이아웃
- **가운데 정렬 과다** — 모든 텍스트가 center인 슬라이드
- **균일한 둥근 모서리** — 모든 카드/박스가 같은 radius
- **이모지 남용** — 제목이나 불릿에 이모지를 디자인 요소로 사용
- **제네릭 제목** — "핵심 기능", "왜 우리인가", "Our Solution" 등 AI 생성 느낌의 범용 제목

발견 시 P1(중요) 이상으로 분류하고, 구체적 대안을 제시한다.

### 스토리 아크 체크

```
도입(왜 이 이야기를 하는가)
  → 문제(무엇이 문제인가)
    → 해법(어떻게 푸는가)
      → 증거(실제로 작동하는가)
        → 미래(어디까지 갈 수 있는가)
          → 행동(지금 무엇을 하면 되는가)
```

### 기술 과장 감지

다음 표현이 있으면 플래그:
- "리버스 불가", "해킹 불가" → "높은 리버스 비용", "실질적 보호"
- "원천 차단" → "효과적 방어"
- 검증 없는 성능 수치

## 출력 형식

### 페르소나별 섹션

디자이너 페르소나는 **질문형 비평 화법**을 사용한다 (`../../resources/ai-slop-checklist.md`의 "디자이너 비평 화법" 참조). 지시형("바꿔라")이 아닌 관찰/질문형("~이 눈에 띕니다. ~하면 어떨까요?")으로 피드백한다.

```markdown
## [페르소나명] 관점

**전체 인상**: 1-2줄
**강점**: 3개 (번호)
**약점/개선**: 번호, 구체적 슬라이드 지정
**수정 제안**: 어떤 슬라이드에 무엇을 추가/수정/삭제
```

### 통합 액션 아이템 (마지막)

P0부터 P3까지 우선순위 테이블로 정리.

## 참조 문서

- **`references/personas.md`** — 5개 페르소나의 상세 평가 기준, 질문 목록, 채점 기준
- **`../../resources/ai-slop-checklist.md`** — AI 생성 디자인 안티패턴 블랙리스트 10가지 (슬라이드 특화 항목은 위 "AI Slop 체크" 섹션 참조)
