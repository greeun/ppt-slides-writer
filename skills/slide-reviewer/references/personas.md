# 페르소나별 상세 평가 기준

## 1. 투자자 (VC 심사역)

### 핵심 질문

| 항목 | 질문 | 점검 포인트 |
|------|------|-----------|
| 시장 기회 | 시장이 충분히 크고 성장하고 있는가 | TAM/SAM/SOM이 모두 명시되어 있는가 |
| 문제 정의 | 풀려는 문제가 실제로 존재하고 고통이 큰가 | 데이터 출처가 명시되어 있는가 |
| 해법 차별화 | 기존 대안 대비 10배 이상 나은 점이 있는가 | "nice-to-have"가 아닌 "must-have"인가 |
| 비즈니스 모델 | 수익 구조가 지속 가능한가 | ARPU, 전환율, LTV 등 핵심 가정이 있는가 |
| 매출 전망 | 성장 곡선이 현실적인가 | 연도별 성장 근거(고객 수, 가격)가 있는가 |
| 경쟁 해자 | 모방 방어가 충분한가 | 네트워크 효과, 특허, 전환 비용 등 |
| 팀 | "왜 이 팀인가"가 설득력 있는가 | 도메인 전문성, 트랙 레코드, 어드바이저 |
| 자금 계획 | 투자 소요와 사용처가 명확한가 | 번레이트, 런웨이, 자금 조달 계획 |

### 주의할 점

- 매출 전망의 "하키 스틱" 곡선에 근거가 없으면 P1으로 플래그
- 경쟁사 분석이 한 줄짜리면 P2로 플래그 (특히 펀딩 받은 경쟁사)
- 팀 슬라이드가 없으면 P1으로 플래그

## 2. 기술 경영자 (CTO/기술 임원)

### 핵심 질문

| 항목 | 질문 | 점검 포인트 |
|------|------|-----------|
| 기술 선택 | 언어/프레임워크 선택이 합리적인가 | 선택 사유가 명시되어 있는가 |
| 완성도 | 현재 상태가 솔직하게 표현되었는가 | 과장된 완성도 수치가 없는가 |
| 아키텍처 | 확장 가능한 구조인가 | 기술 부채 리스크가 언급되는가 |
| 보안/보호 | 기술 보호 주장이 정확한가 | "불가"가 아닌 "비용이 높다"로 표현되었는가 |
| 일정 | 개발 일정이 현실적인가 | 인력 대비 일정이 과도하지 않은가 |
| 통합 | 제품 간 통합이 기술적으로 타당한가 | 공유 DB, API 설계가 합리적인가 |

### 기술 과장 감지 패턴

- "리버스 불가", "해킹 방지" → P0 플래그
- "원천 차단", "완전한 보호" → P1 플래그
- 검증 없는 성능 수치 ("10배 빠른") → P1 플래그
- Go 바이너리를 Rust와 동급 보호로 묶는 표현 → P1 플래그

## 3. 사업 파트너 (채널 파트너)

### 핵심 질문

| 항목 | 질문 | 점검 포인트 |
|------|------|-----------|
| 수익 구조 | 파트너가 돈을 벌 수 있는 구조가 명확한가 | 마진/배분 비율이 예시라도 있는가 |
| 역할 분담 | 프렌티스 vs 파트너 역할이 명확한가 | 회색 영역이 없는가 |
| 첫 단계 | 당장 할 수 있는 액션이 구체적인가 | 일정, 대상, 방법이 명시되었는가 |
| 리스크 | 리스크가 투명하게 공개되었는가 | 제품 지연, 시장 변화 등 |
| 소스 접근 | 소스 미제공 정책이 파트너에게 불이익은 없는가 | 바이너리/SaaS만으로 충분한가 |
| 장기 비전 | 파트너 관계가 장기적으로 발전하는가 | 단순 리셀러가 아닌 생태계 파트너인가 |

### 주의할 점

- 수익 배분 비율이 "협의"만 있으면 P1 플래그
- 파트너 ROI 시나리오가 없으면 P2 플래그
- 리스크 공유 방침이 없으면 P2 플래그

## 4. 디자이너/프레젠테이션 전문가

### 핵심 질문

| 항목 | 질문 | 점검 포인트 |
|------|------|-----------|
| subtitle | 모든 콘텐츠 슬라이드에 subtitle이 있는가 | SectionDivider 제외, SlideLayout은 필수 |
| 정보 밀도 | 슬라이드 간 정보량이 균일한가 | 너무 비거나 너무 과밀한 슬라이드 지적 |
| 여백 | 불필요한 빈 공간이 과다하지 않은가 | padding, 컴포넌트 배치 효율성 |
| 텍스트 양 | 텍스트가 충분하면서 넘치지 않는가 | 불릿 3~5개, 문장 6줄 이내 |
| 시각 요소 | 차트/이미지/테이블이 적절히 활용되었는가 | 텍스트만 있는 슬라이드가 연속되지 않는가 |
| 색상 일관성 | 테마 색상이 일관되게 사용되었는가 | primary, secondary, accent 혼용 없는가 |
| 중복 | 동일 정보가 반복되지 않는가 | title과 본문, subtitle과 본문 중복 |
| 특수 기호 | 화살표(→↑↓) 등 축약 기호가 없는가 | 볼트 규칙 위반 체크 |
| 격식체 | 합쇼체가 일관되게 사용되었는가 | 구어체/반말 혼입 없는가 |

### 체크리스트 (슬라이드별)

각 슬라이드에 대해:
1. title이 있는가
2. subtitle이 있는가 (SectionDivider 제외)
3. sectionLabel이 있는가
4. 콘텐츠가 화면의 60% 이상을 채우는가
5. 시각 요소가 최소 1개 있는가 (테이블, 차트, 카드, 이미지)
6. 텍스트가 읽기 적절한 크기인가

## 5. 발표자 (CEO)

### 핵심 질문

| 항목 | 질문 | 점검 포인트 |
|------|------|-----------|
| 스토리 아크 | 도입→문제→해법→증거→미래→행동 흐름이 있는가 | 각 섹션이 이 아크의 어디에 해당하는가 |
| 핵심 메시지 | 각 슬라이드가 1줄 메시지로 요약 가능한가 | title이 핵심 메시지를 전달하는가 |
| 시간 배분 | 장수 대비 발표 시간이 적절한가 | 장당 1.5~2.5분이 적정 |
| 섹션 전환 | SectionDivider가 자연스러운 전환점인가 | 갑작스러운 주제 변경이 없는가 |
| 에너지 | 청중 집중을 유지할 수 있는가 | 데이터 슬라이드가 3장 이상 연속되지 않는가 |
| 클로징 | 마무리가 인상적인가 | 행동 유도(Call to Action)가 명확한가 |
| 데모 | 제품 데모/스크린샷이 포함되었는가 | 전체가 텍스트 기반이면 P3 플래그 |

### 스토리 아크 매핑

각 섹션이 아크의 어디에 해당하는지 매핑한다:

```
도입: S0 오프닝
문제: S1 산업 배경
해법: S2 비전 + S3 제품
증거: S4 로드맵 + S5 비즈니스
미래: S6 교육 + S7 파트너십
행동: S8 클로징
```

이 매핑이 자연스러운지, 빠진 단계가 없는지 점검한다.

## 우선순위 기준

| 우선순위 | 기준 | 예시 |
|---------|------|------|
| **P0** | 사실 오류, 규칙 위반, 핵심 누락 | subtitle 누락, 기호 축약, 기술 과장 |
| **P1** | 설득력 저하, 핵심 데이터 부재 | 매출 근거 없음, 팀 소개 없음, 수익 배분 미정 |
| **P2** | 구조 개선, 정보 재배치 | 정보 과밀, 시간축 중복, 슬라이드 축소 |
| **P3** | 선택적 개선 | 데모 추가, 듀레이션 조정, 3D 시각화 |
