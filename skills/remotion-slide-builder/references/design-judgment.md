# 장표 타입 선택·디자인 판단

같은 컴포넌트나 같은 틀을 기계적으로 반복하면 슬라이드가 단조로워집니다.
이 문서는 어떤 장표 타입을 고를지, 어떻게 반복을 피할지, 무엇을 자동화하고 무엇을 손으로 판단할지를 정리합니다.
앞부분은 반복을 막는 판단 규칙이고, 뒷부분은 콘텐츠 유형별 시각 요소를 고르는 참고 사전입니다.

## flow 장표 자동 남발 금지

흐름도(flow) 장표를 자동으로 찍어내면 이미 관계가 설명된 내용을 또 다이어그램으로 그려 중복이 생깁니다.

| 장표 타입 | 자동 생성 |
|-----------|----------|
| pipeline(가로 순차 흐름) | 허용 |
| swimlane(역할별 레인 흐름) | 허용 |
| hub-spoke(중심·방사 관계) | 기본 금지 |
| module-map(모듈 지도) | 기본 금지 |
| 정의형 다이어그램 | 기본 금지 |
| 계층형 다이어그램 | 기본 금지 |

- pipeline과 swimlane은 순서·역할이라는 새 정보를 시각화하므로 자동 허용합니다.
- hub-spoke, module-map, 정의형, 계층형은 본문에서 이미 관계를 말로 설명한 경우가 많아 그대로 다이어그램화하면 중복입니다. 꼭 필요할 때만 손으로 판단해 추가합니다.
- 근거: 모든 관계를 다이어그램으로 바꾸면 장표마다 비슷한 그림이 반복돼 오히려 지루해집니다.

## 카드형 단독 반복 금지

ConceptCard 같은 카드형만 연속으로 쓰면 장표 리듬이 사라집니다.

- 리스트, 비교표, 흐름도, 코드, 실습 절차, Q&A, 체크포인트를 섞어 다양화합니다.
- 근거: 같은 형태가 5장 연속이면 수강생은 화면 구조를 예측해 버리고 집중이 풀립니다. 형태 변화가 곧 주의 환기입니다.

예시: 개념 3장을 모두 ConceptCard로 만들었다면, 다음 장은 비교표나 코드 해설로 바꿔 흐름에 변화를 줍니다.

## 공통 Intro/Checkpoint 복제 금지

여러 단원이 같은 Intro·Checkpoint 틀을 쓰는 것 자체는 괜찮습니다. 문제는 본문까지 복사되는 경우입니다.

- 틀(이론·예제·구조·판단)은 유지합니다.
- 본문은 **그 단원에서만 길러야 할 판단 능력**으로 좁힙니다.
- 근거: 틀은 일관성을 주지만 본문이 같으면 단원이 달라도 같은 강의처럼 느껴져 학습 가치가 떨어집니다.

## 강의 목적 정렬

장표 흐름이 강의의 목적에서 벗어나지 않게 점검합니다.

- 설계를 가르치는 강의가 검수·거버넌스 체크리스트로 흘러가지 않게 합니다.
- 성격이 다른 산출물의 흐름 단계를 섞지 않습니다.
- 근거: 목적과 다른 산출물이 끼어들면 수강생이 "이걸 왜 배우지"라고 느끼고 강의의 일관성이 무너집니다.

## 실습 강제 안 함

모든 LO에 실습을 끼워 넣을 필요는 없습니다. LO 성격에 맞춰 구성합니다.

| LO 유형 | 장표 구성 방향 |
|---------|---------------|
| 이론 LO | 리서치, 표준, 판단 기준, 토론을 강화 |
| 실습 LO | 폴더·입력·필드·금지·완료 기준을 단계별(step-by-step)로 |

- 근거: 이론 LO에 억지 실습을 넣으면 내용이 얕아지고, 실습 LO에 단계가 빠지면 수강생이 따라 하지 못합니다. 유형에 맞는 충실도가 밋밋함을 막습니다.

## 의미 라벨 사용

라벨은 순번이 아니라 내용으로 붙입니다.

- 금지: "판단 기준 1 / 2", "Check 2"처럼 순번만 든 라벨
- 권장: "근거 기반 응답", "권한과 감사"처럼 내용을 담은 라벨
- 근거: 순번 라벨은 정보가 없어 수강생이 다시 본문을 읽어야 합니다. 내용 라벨은 그 자체로 요점을 전달합니다.

## 조밀 변형 spacing 메모

다이어그램형 장표는 빈자리가 커 보일 때가 있습니다. 표준 theme spacing을 바꾸지 말고, 해당 장표에서만 아래 조밀 변형 값을 적용합니다.

| spacing 토큰 | 표준 | 조밀 변형 |
|--------------|------|----------|
| page | 80 | 60 |
| section | 48 | 36 |
| element | 24 | 20 |

- 표준 spacing은 그대로 두고, 빈자리가 두드러지는 다이어그램 장표에 한해 위 값을 인라인으로 적용합니다.
- 근거: 표준 값을 전역에서 바꾸면 모든 장표 레이아웃이 어긋납니다. 조밀 변형은 빈자리 문제를 가진 특정 장표에만 국소 적용해야 안전합니다.

## 콘텐츠-시각 매핑 사전

아래는 규칙이 아니라 영감을 주는 참고 사전입니다. 상황에 맞게 변형하십시오.

| 콘텐츠 유형 | 시각 요소 후보 |
|------------|---------------|
| 로드맵, 일정, 마일스톤 | 타임라인(가로/세로), 간트 차트, 프로그레스 바 |
| 성능 비교, KPI | 가로 바 차트, 도넛 링, StatCard |
| 프로세스, 파이프라인 | 플로우 카드, 화살표 흐름 다이어그램 |
| 시장 규모, 스케일 | 동심원(TAM/SAM/SOM), 원형 프로그레스 |
| 추상 개념, 메타포 | 이미지 생성(image-gen), 삽화 |
| 숫자·통계 나열 | StatCard 그리드, DataTable |
| 텍스트 목록 | AnimatedList, ConceptCard |
| 코드 설명 | CodeBlock + 우측 설명 2컬럼 |
| 팀 구성, 조직 | DataTable, 카드 그리드 |
| 핵심 메시지 강조 | 하단 배너, 그라디언트 텍스트 |

## 이미지 vs 코드 판단

모든 장표를 이미지로 만들 필요는 없습니다. 아래 기준으로 판단합니다.

### 이미지가 효과적인 경우

- 시각 메타포가 핵심일 때(감정·상황 전달, 추상 개념)
- 크기·스케일 감각을 전달할 때(시장 규모 동심원)
- 복잡한 관계를 한눈에 보여주는 조감도(아키텍처)
- 단계적 전환의 시각적 흐름(파이프라인)

### 코드 컴포넌트가 나은 경우

- 정확한 수치와 비교가 핵심일 때(성능 목표, ROI)
- 정보 정확도와 정렬이 필수일 때(테이블 데이터)
- 읽어야 하는 텍스트일 때(자격, 실적 나열)
- 자주 수정되는 데이터일 때(이미지 재생성 비용이 큼)

## 레이아웃 구성 사고 과정

콘텐츠를 분해하고 시각 요소를 매핑한 뒤, 여러 조합을 만들어 샘플링합니다.

예시: "여러 단계의 로드맵" 장표

콘텐츠 분석:
- 3단계 타임라인
- 단계별 진행도 프로그레스 바
- 기대 효과 3줄

레이아웃 조합(3안):
1. 좌측 가로 타임라인 + 우측 산출물 상세 + 하단 진행도 프로그레스
2. 좌측 세로 타임라인(진행도 통합) + 우측 기대 효과 카드 + 하단 핵심 메시지
3. 좌측 간트 차트 + 우측 단계별 지표 + 하단 기대 효과

## 코드 우선, 이미지 전환 패턴

코드 컴포넌트로 먼저 레이아웃을 잡고, 결과를 본 뒤 이미지 전환 여부를 판단합니다.

```
코드 컴포넌트로 제작 → Studio에서 확인 → 괜찮으면 그대로 사용
                                        → 이미지가 나으면 image-gen으로 교체
```

장점:
- 코드 기반은 수정이 즉각적입니다(데이터·텍스트·레이아웃 변경이 코드 수정만으로 반영).
- 이미지 전환 여부를 결과물을 보고 판단할 수 있습니다.
- 이미지 재생성 비용(시간·토큰)을 필요한 장표에만 투자합니다.

기본 전략: 일단 코드로 만들고, 이미지 전환은 나중에 판단합니다.
